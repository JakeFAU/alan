# Phase 1F qualification

The runnable application, live measurements, selected crash qualification and complete checks passed final independent review for this bounded increment. Earlier evidence remains immutable. Publication uses a draft PR for the user's review; this is not a production-readiness or general-quality claim.

## What is being qualified

The public `investigation.New` component plans two evidence subquestions, sends both before waiting, synthesizes their public results, obtains an ordinary review, and either delivers a result, stops explicitly, or authorizes one revision. The same component runs directly and behind `Report`, which adds ordinary publication routing. The finite ceiling is 13 model requests and four lookups. No interpreter, scheduler, lifecycle authority, SQLite schema or dependency changes are part of this phase. Optional exact-span exclusions are a versioned lookup input and a public helper request, not a policy opcode.

The useful-application claim is evaluated separately from execution correctness. A model review can approve an incomplete answer. Exact citation bytes establish provenance, not entailment. A stopped diagnostic candidate is never substituted for an absent delivered answer. The frozen rubric and independent grading determine quality; the application reviewer does not.

Original failures remain; current authority may advance while historical authorization stays fixed. Neither correction changed runtime behavior or semantic bounds.

Initial development exposed a validly sized but overlong lexical query, repeated header retrieval, and confusion between missing retrieved evidence and corpus-wide absence. The original prompts, outputs and independent judgments remain. Prompt clarification alone did not solve repeated retrieval. The optional exclusion protocol removes only explicitly named exact spans and guarantees neither relevance nor complete evidence. No failed run or valid input is discarded.

One active executor per store, trusted adapters, static provisioning/grants, one PC per run, immutable retained artifacts and local process-crash storage assumptions remain. No distributed ownership, dynamic spawning, business deduplication, migration, provider catalogue expansion, stable SDK, UI, power-loss test, unbounded fairness or general semantic equivalence is claimed. A fresh authorized revision is distinct from repeating an uncertain operation. Dormant static helpers may remain waiting. No production-readiness claim follows from review approval.
