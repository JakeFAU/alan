# Authoring slice integration notes

These are narrow implementation choices for the planned application, to be checked by compiler tests and reported as concrete interfaces before adapter/application work.

The current `map[string]Value` is already a flat typed record of string, integer and boolean values. The first application can use that representation without adding an object interpreter: planning fields `decision`, `tool`, `query`, `message`; retrieval fields `found`, `document`, `version`, `snippet`, `start`, `end`; synthesis fields `answer`, `document`, `version`, `quote`, `start`, `end`. Nonselected planning fields can be empty strings. The final single citation must equal the retained lookup document/version/snippet/offset fields. More general arrays, arbitrary nested JSON, multiple citations and arbitrary schema dialects are not necessary for this increment.

The public author package should expose named declarative steps/builders, not raw executor opcodes or numeric positions. Structured author steps may compile into existing branch/jump/set/add/emit/receive/end instructions. Bounded repetition can compile to a statically bounded expansion; runtime turns remain one finite instruction. Reject missing/duplicate labels and inconsistent variable/binding types with author names and positions. Definite assignment must hold along every predecessor path that reaches a reference. Test empty/zero repeats, loop exits and shuffled map insertion order. Persist a compiler version and position/name mapping rather than depending on Go source after restart.

A small public runtime facade can export safe aliases/wrappers of the existing executor types and lifecycle, then the author package can compile into its provision/artifact types. Avoid an import cycle and do not duplicate the scheduler or reducer. An external module must import only public packages. Static application construction should fill generation/revision defaults and generate explicit grants from declared wiring/effects so application authors do not manipulate epochs, SQL or authorization ledgers. The lower-level API can remain explicitly provisional; no general SDK ecosystem is implied.

Schema declarations must be locally immutable/canonical and available at recovery. A narrow closed flat-record schema (required fields, scalar kinds, finite enums/string bounds, no additional fields) is sufficient. Define it in a shared pure location that compiler, adapter validation and replay can consume; this shared validation is not an independent oracle. Retain both schema identities and bytes in the artifact. Prompt strings and literal stage descriptions must be retained. A new author semantic/artifact version may wrap the same generic instruction basis; legacy programs must keep exact supported semantics and byte identities or be rejected explicitly. Version-2 store schema does not imply all program versions are identical.

Ordinary message correlation already includes source execution and obligation. Request/result APIs should provide a named request identity/obligation and public endpoint contract; they must not infer current child generation or inspect private state. The first application is one bounded question per provisioned workflow. Reusable composites may be statically instantiated more than once, with distinct wiring and obligations. Document this instead of implying a long-lived multi-tenant service or dynamic child creation.

The next slice will need to attach a deployment-configured adapter registry to the existing Store/Run path without importing provider code into the reducer. Compiler effect declarations should identify a fixed adapter capability and input/output schema, with an ordinary correlated receive of a runtime-validated result envelope. `valid`, disposition and schema/result fields are data the ordinary program consumes and branches on. No adapter result can directly call another adapter. Effect commitment may atomically update logical spent counters through the existing generic Updates map.

Exact Go signatures are deliberately frozen by the reviewed Task 2 report, not guessed independently by later implementers. This note narrows the required capability; it does not replace tests for the contract.
