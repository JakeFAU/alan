# Phase 1E authoring, effects and recovery contract

This increment extends the single-host executor; it does not replace it. Authoring runs once to produce immutable versioned bytes. Runtime residual control remains explicit finite instructions; no captured Go closures or stacks enter recovery. The compiler retains names, typed input/output/effect schemas and prompt/template bytes. Identifiers must be nonempty valid UTF-8 and are never normalized; invalid byte names are rejected before serialization so distinct names cannot collapse. Valid composed and decomposed Unicode names remain distinct. A public facade delegates to the same Store/Run, with no second scheduling loop.

A fresh schema-version-3/key-version-2 store receives a random 256-bit namespace in its provisioning transaction. External keys canonically encode key version, namespace and existing local intent identity. Reopen/rename preserves it; a copy preserves the same namespace and is not a new independent store. Concurrent independent use of copies is unsupported. The namespace slice first used schema 2; the adapter/asset ledgers advance the layout to schema 3 without changing key version 2. Schema 1 and intermediate schema 2 stores are explicitly rejected for live execution before activation/dispatch; no automatic migration/rekey is supplied. Historical evidence remains reproducible with its retained source. Namespace uniqueness does not deduplicate business work.

Adapters are named deployment-configured capabilities. An immutable committed intent, source authorization, declared effect schema and static grant precede a transport launch. Names, endpoints, headers and rights cannot be supplied by model output. Fixture counter transport remains loopback-only. Model and lookup work share the existing bounded Run owner and completion accounting. Adapters execute one effect and return a correlated candidate; only the owner validates durable identities, records outcomes and admits observations. Ordinary programs alone choose the next branch or lifecycle policy. Adapters are trusted Go infrastructure: Prepare is required to be pure, bounded and nonblocking, while Execute respects cancellation. This contract is not a sandbox for arbitrary callbacks and does not enforce those obligations on malicious implementations.

Model input retains explicit model ID, instructions, full stage input, schema and selected output bounds. The thin Responses adapter has one nonstreaming request, no hidden retry/redirect/tool loop, no remote conversation dependency and no idempotence assumption. Requested and returned model names are distinct; a mutable alias is not a weights pin. Runtime credentials are not artifact, journal, inspection or evidence fields. The response retains bounded replay-relevant evidence, IDs, actual optional usage and validation/disposition. Evidence is sanitized, not always byte-identical to the wire. Returned strings and JSON details that exceed the sanitizer’s decoding/inspection budgets or cannot be safely inspected are omitted; altered evidence cannot remain validated success. This can also omit benign unusually encoded diagnostic content. Provider rejection, refusal, incomplete output, schema-invalid output and unknown transport are explicit. They never become validated application success.

An authorized model request without a recorded result may have executed remotely. Reopen retains Unknown and performs no automatic inference. This increment provides no intentional repeat/reconciliation policy. A recorded result is reused; receipt recording, observation settlement and ordinary consumption remain separate commits. Known-but-unsettled evidence is pending, not Unknown. Cancellation stops physical work without logically cancelling applications. Valid late evidence settles its original obligation without reopening a run. Live recovery has dispatch authority; historical replay does not.

The initial evidence assistant uses bounded flat typed decision/result records and one citation. Successful flow is ordinary message input, first model intent/result, decision validation, ordinary retrieval request, separately authorized lookup result, second model intent/result, citation validation and reply. It also supports clarification/insufficient evidence and explicit invalid-result failure. The helper is a statically provisioned ordinary composition; its caller sees only its request/result boundary. No runtime opcode or role type embodies this policy.

The corpus is a bounded immutable snapshot retained in the store before execution; source paths are provenance, not recovery dependencies. Lookup returns document identity, content version, exact snippet and byte offsets. The ordinary final checks require the quoted snippet/document/version/start/end to match the retained evidence. This establishes mechanical citation provenance, not substantive correctness of every answer sentence.

Logical per-question budgets are program data (default ceiling 3 model requests and 2 lookup requests); ordinary effect commitment spends them atomically. Physical reopen preserves spent counters and pending identities. Logical requests, allowed durable attempt reservations, denied decisions and unknown usage are separately inspectable. A reservation does not independently establish that a provider received a request; qualification counts remote contacts separately. Operational body/token/corpus limits are explicit and finite, independent of research-model bounds. Each example uses at most two model requests and one lookup on its normal path; remaining configured capacity is not a hidden repair loop.

Qualification uses the real provider serializer/parser with controlled HTTP responses and independent contact records. Default tests need no credential or expenditure. A live command requires an explicitly selected model and runtime credential. Current environment has neither; live is NOT RUN unless configuration becomes available. Finite successful traces and process-kill evidence do not establish unbounded fairness, arbitrary-depth equivalence, safe repeated business work, power-loss durability or production readiness.


The model input may be a caller-selected flat record of question and evidence fields. With an instructions string, the adapter serializes all remaining scalar fields as canonical native JSON into one user message. The exact two-field instructions/input-string shape retains a text convenience. Both forms retain the complete request before dispatch; neither introduces a prompt-formatting opcode or chooses an application branch.
