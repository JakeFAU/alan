# Executor realization and directed checks

The principal proof edge is the query's retained ordinal, its independently decoded snapshot and the original's separate tagged result. The unchanged first authorization, attempt and charge belong to the original. The new physical read has its own current activation, bound read ordinal and query key. A found snapshot under the success contract can reconstruct the original typed return. An existing ordinary candidate keeps its exact encoding. These are implementation properties of schema 5 under the frozen trust assumptions.

## Where to inspect the evidence

* `internal/executor/reconciliation_profile.go` stores exact resolver, target locator, ledger-pinned endpoint and adopt bit. Creation requires a composition deployment. An empty list denies every target. Legacy deployments keep schema 3 or 4. A schema-5 database identified as legacy is rejected when its receipt tables survive.
* `internal/executor/receipt_read.go` authenticates the original allowed attempt and protocol, derives its exact old wire, and separates its preparation digest from its wire SHA-256. The normal gate, under its existing short exclusions, rechecks resolver authority and the original terminal source's local drain. Both actors must be composition members in this profile. It inserts one `receipt_read_ordinals` row and an ordered `receipt_read` composition fact in one transaction. Only then does the physical reader receive that bound query outside Store exclusion. No original mutation enters this service function.
* The ordinal's `Prefix` is the composition order immediately before its spend fact. Its `Resolver` is the current physical authority and can differ from the query's first authorization on a successor. `dispatch.admitted/pre-call`, `adapter.response/pre-record` and `adapter.result-recorded/pre-settlement` carry the query identity. A corrected hook takes the current read epoch from the durable ordinal.
* `receipt_result.go` verifies the actual response bytes, transport status, unassessed payload and full ordinal. One transaction writes the query result with `Read` and, where justified, the previously missing original with `Reconciled`. The original contains its original operation ID, the query ID/ordinal and the immutable application receipt. Its ordinary `Candidate` is the Go zero value. `Read.Adoption` distinguishes adopted, duplicate, existing, denied, evidence_only, unsupported_policy, conflict and none. The program sees adopted true only on the first successful import. Query transport errors have typed unsuccessful defaults. All genuine snapshots, including absence and conflict, remain in their own query response bytes.
* `settleRecordedDispatch` services both locally after the import transaction. Resolver accounting settles the imported original before the query. A failed settlement belongs to the resolver's accounting lifetime; an ordinary policy refusal settles locally. The aggregate's readiness and parent selection remain separate existing transitions.
* `receipt_replay.go` checks both ends of a claimed import, read capability/preparation, exact target and full original attempt, wire preimage, gap-free bounded ordinals, increasing activation on repeat, actual grant and read-only receipt interpretation. The composition prefix checker tests original closure and resolver eligibility at the recorded historical prefix; the next fact must describe that exact read ordinal. Removing the sole unreturned ordinal leaves an unexplained spend fact. For a successful import, the query and original result facts are adjacent with the query first. A resolver settlement that claims a successful import requires the corresponding original settlement. Replay uses no registered adapter or endpoint.
