# Implementation and qualification sequence

1. Verify the rebased integration tree and both historical evidence inventories. Reproduce the static identity/consumption handshake, the dynamic template obstruction, and a minimally extended dynamic positive using ordinary typed messages in a separate public module. Preserve the actual target, consumed ACK, truthful issuance reply, successful original source and pending captured obligation on an inspected/replayed store. Review and freeze this constructor, its negative controls, the grant/wire/retention interfaces and the prospective case matrix before implementing reconciliation or writing the reference oracle.
2. Build an implementation-independent finite transition model from that frozen contract. Enumerate complete labelled outgoing edges and service conditions per profile, retain actual negative traces and mutated exports. A separate reviewer checks the outgoing rules, including provisional absence, differing authority and retained rather than returned outcomes.
3. Implement an explicit format-2 endpoint ledger and query route. Validate the route, body, immutable application receipt and canonical snapshot. Implement opt-in retained Store support and exact target binding, spend-before-L physical allowance and current resolver admission. Write genuine behavioral REDs before each relevant change. Preserve old owners' schema rejection, old-format behavior, legacy no-repeat properties and the closed-template domain. Independently inspect the gate, result/adoption transaction, Q recovery and replay/corruption checks.
4. Run the positive and the identity/authority/immutability controls using public programs and controlled endpoints. Capture selected observation IDs and fields, causal handoffs, original charges, query charges and separate ordinal costs. Probe capacity-one lookup, late resolver cancellation, endpoint replacement, configuration/metadata conflicts and equivalent imports from two resolvers. A disposable malformed store is negative evidence only.
5. Run the paired, delayed packet, loss-of-absence, spent ordinal, post-commit recovery, immutable unsuccessful interaction and replay families on original databases with real subprocess SIGKILL and new ownership. Record binaries, source, barrier identities and independent endpoint state. Audit the evidence separately from the Go implementation. Use normal and race executables for runtime, children, endpoint, model and separate consumer. Run affected Phase 2A/B gates, formatting, vet, both module verifications, and one complete ordinary root suite with a 60-minute per-package timeout and `-p=2`. Preserve any unsuccessful selection and qualify repaired sources explicitly.
6. Reconcile the evidence with Pillars IV and V and the existing no-channel counterexample. Have the substantive source reviewed before the single Tectonic invocation, inspect the rendered pages, seal the source/evidence index and obtain independent final disposition. Make focused commits, publish a draft PR against the verified integration base and stop there.

The integration base is the common comparator for all implementation REDs. Per-command source manifests distinguish typed constructor changes from model, production, fixtures and later corrections. Local temporary build products and exploratory artifacts that do not constitute evidence are outside the packet.
