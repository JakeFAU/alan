# Phase 2C process recovery matrix

This prospective plan asks which original and query facts survive the death of a real Store owner and which facts require a new authorized read. It covers one host, exclusive Store ownership, a separately running format-2 endpoint, and the trusted protocol in the frozen contract. The matched branches are counterfactual executions from the same initial state. A successful Q refers to the original source generation under the current owner. A read indication, original result, settlement, publication and ordinary selection each need their own witness. ## Apparatus

Use integration tests under `internal/durabletest/phase2c_*_test.go`. Reuse `phaseTestProcess`, the barrier and command pipes, `child.kill`, `phaseFinish`, `phaseRawStore`, `phaseProvenance`, and the normal/race binary builder. Add a format-2 launcher using the existing binary and startup protocol. Keep legacy tests and captures intact. Launch each owner as a fresh exec of the current instrumented test binary. It opens the original branch database and runs ordinary work at capacity one with the concrete protocol registry. The parent observes committed state but supplies no target, receipt, application knowledge or branch decision to a program.

Use the public construction for the adapter histories. The original invocation member emits the original request, hands off its genuine operation identity through the authored exchange, and succeeds after its ordinary acknowledgment. The resolver is outside that invocation. Its empty start and optional refresh inputs only authorize the fixture to schedule the next stage. The real program obtains its original and resolver outcomes through the declared ports. Obtain the actual source RunID from the invocation binding for host quiescence. Prove the closed original has a permitted and debited attempt, captured original operation and pending publication before allowing the first read. The fresh owner returns a PID-tagged `AwaitDispatchQuiescence` acknowledgment naming namespace, subject and generation; recovery with an open resolver proves activation renewal independently of the closed original's unchanged epoch.

Use a compact separate process fixture for the raw comparisons. Its source emits the existing raw external operation, forwards the genuine ID in an ordinary message, and can actually close after the worker is admitted. The resolver executes the same trusted read capability against that committed raw request. Raw lookup is qualified through its ordinary selected evidence, exact raw authorization/epoch-bearing wire, and evidence-only or conflict disposition. It supplies no original adapter success claim.

## Evidence boundary

Validate each executor acknowledgment against the configured process, nonce, database, boundary, run, original or query intent and authorization. A later source projection may have advanced beyond the original emission sequence. Check the exact intent sequence against its committed descriptor, and validate the distinct current source/R fact directly. A query ordinal belongs to its logical query, its unique target binding, owner activation and durable reservation. A held endpoint's ingress event must match the original wire and ledger identity. A post-response cut must match a real endpoint snapshot, and a post-retention cut must match actual new rows. Never credit a signal before acknowledging the intended cut. Use ordered commands, synchronized barriers and durable predicates for causal order; a timeout reports missing progress.

Archive named coherent local and world SQLite backups and independent append-only journal at the determining cuts, plus a compact per-case transcript linking each acknowledgment, release, PID/token, kernel exit status and selected inputs. Record semantic debits, physical opportunities, lookup contacts, mutation contacts and genuine applications separately. Use direct SQL or independent inspection on read-only backups. Never populate authoritative rows using SQL. Independent audit belongs to the phase-wide auditor. At each kill prefix and completed outcome, replay the local database while external service is held constant. Check complete local and endpoint tables and journal bytes before/after, including lookup audit rows. Link the before/after observations by case and cut for later audit.

The intended selectors are `go test -tags integration ./internal/durabletest -run '^TestPhase2C' -count=1 -v` and the same invocation with `-race`. Use `docs/foundational/phase2c/tools/record.py`, separate evidence directories, immutable run inputs and the repository watchdog. Source-bound RED, failures and corrected results belong to the qualification. No execution is claimed by this matrix. The construction suite owns the live consumer and immutable failed-interaction controls. Runtime qualifications own actual sticky local accounting failure, concurrent import and authority-order controls.
