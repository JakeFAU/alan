# Runtime source map and proposed boundary

This is the pre-implementation design. The construction and independent specification reviews determine whether its proposed capability can enter the executable. The question is whether the Store can use an authorized query result to discharge one missing original adapter result, while preserving an already recorded interaction. The smallest boundary includes both the worker that performs a physical read and the transaction that validates and retains its evidence.

## Existing behavior at the integration base

* `internal/executor/program.go`, `Reduce` emits an operation identity as the JSON tuple of source subject, generation, durable sequence and ordinal zero. A string delivered by a program has no proof that the tuple denotes a committed operation. `adapterRequest` reopens the retained program, requires an effect declared at its obligation and checks its input schema. Its own key is `ExternalKey(namespace, id)`.
* `internal/executor/adapters.go` stores the whole `Prepared` plus the first source authorization and reservation decision. `effects.Freeze` hashes the JSON preparation including request, configuration, schemas and wire string. This differs from SHA-256 of `Prepared.Wire`. The Phase 2A counter wire contains just key, profile and delta. The raw path in `external.go` sends `json.Marshal(attempt.Request)` including the actual source/epoch/authorization fields. Existing fixtures re-marshal parsed bodies. Their records alone cannot establish exact wire equality.
* `runner.go` calls `retryEligibleWork`, prepares one request, obtains a Phase 2B dispatch opportunity, and hands work to a bounded worker. `Run` accounts returned data even on shutdown. `dispatch.go` registers A under the Store mutex, releases it before L, holds the opportunity through accounting, and remembers the first per-source accounting failure. An old allowed adapter attempt with missing result withholds re-exposure. The current schema has nowhere to reserve or validate fresh physical read ordinals.
* `loadAdapterResult` requires `Candidate.ID`; `recordAdapterResult` and `validateAdapterResult` recover typed values from the candidate and disposition. Passing a fabricated successful original candidate through this path would invent an original response. `settleAdapterLocked` records the typed observation and delivery transaction, including for a closed run. In `invocation_outcome.go`, `prepareCompositionScope` tests for a retained result for each captured adapter operation. The successful publication uses the earlier public reply and freeze. It can be ready immediately after result retention, even before settlement. The required schedule must distinguish all three commits and actual selection.
* `composition_replay.go` and `composition_prefix.go` bind original result bytes into ordered composition facts. `composition_reservation.go` debits a member effect once per logical operation. The new logical query must participate in the same machinery. Two physical read opportunities must not produce two semantic charges.
* `store.go` creates plain schema 3 or composition schema 4. `replay.go`, `inspect.go`, `invocation.go`, `composition_store.go`, and `composition_reservation.go` dispatch by schema or verify a composition profile. An old reader must reject a new representation up front. Preserve schema 3 and 4 creation/open/replay interpretation for existing profiles. Keep existing program semantics, key derivation, adapter candidate bytes, and effect allowances.

## Proposed interface

Opt into schema 5 on creation with public `Provision.Reconciliation *ReconciliationProfile`, requiring existing composition protocol provisioning. Keep one immutable profile of at most a small bounded number of `ReceiptGrant` rows. Each row contains the exact resolver `RunID`, a locator selecting one original operation, a ledger-pinned original mutation URL, and `Adopt bool`. An enumerated grant confers read access. For a static source the locator is `Original RunID, Sequence int64`. For a dynamic member use `Invocation string, Member string, Sequence int64`, where `Invocation` is a specific caller operation ID. The latter authenticates actual member binding/invocation, materialized with the current Store namespace. Ordinal is zero. Reject empty, ambiguous, conflicting and duplicate locators. No program can install a grant. Normal adapter permissions and charge/reservation rules for the resolver's own logical operation still apply.

The endpoint-owned `adapters/receiptquery` package supplies concrete `Counter` and `Reader` types, canonical route checking, candidate decoding and public schemas. The principal adapter uses the exact new counter protocol, mutation schema `{delta:int}`, success policy and outputs `{mutation:int,total:int}`. The runtime supplies the bound call to `Reader.ExecuteRead`. Its ordinary `Execute` refuses. The runtime must never treat an arbitrary interface implementation, protocol name, HTTP method, or program string as the trusted read protocol; reject substitution on the original opted-in counter and lookup capability as well. The resolver declares `phase2c.receipt-read`, input `target:string`, outputs `status:string`, `target:string`, `mutation:int`, `total:int`, `adoption:string`, `adopted:bool`, plus the existing result envelope. Target fields and bounds match the public protocol package. `Reader.Prepare` remains pure.

A worker gets a private copy of its immutable bound query, original wire and read ordinal, never the Store. Physical I/O uses only the exact sibling `/phase2c/<64-lowerhex-ledger>/lookup` of `/phase2c/<same-ledger>/apply`. The original URL pins ledger identity across endpoint restart or replacement. A trusted controlled ledger atomically binds the body accepted by the mutation to the immutable application receipt and returns identified counted snapshots. Raw non-idempotent and keyed mutation attempts support read evidence only. More than one application is an explicit conflict.

## Retention and recovery sequence

1. Retain the resolver's ordinary allowed/denied logical attempt using its own effect declaration, key, first authorization and debit. Match an exact read grant to the target string, resolve the genuine original intent, original allowed authorization+attempt, physical endpoint, protocol and wire. For the adapter also check concrete preparation, exact schemas, configuration, body and full preparation digest. For raw reconstruct only the frozen Go JSON wire. A bad target, missing attempt, unsupported historical route, missing grant or route mismatch produces a classified local refusal and no call. Distinguish an ordinary grant denial, source closure, exhausted read opportunities and unsuccessful transport.
2. Restrict the positive domain to the terminal original generation. Recheck exact-source Q under the current owner: terminal source, absence of live writers and sticky handling errors, and no unaccounted original result for that source. Read admission must not block the runner waiting for a completion that only that runner could service. Existing pending original evidence can first be settled using local service. At A hold the normal short authority/owner exclusion, check resolver eligibility, prior query result, allowance and original Q conditions, insert the next durable ordinal (1 or 2) and associate it with that physical opportunity. Commit before L. Retain the query's own ID/key, ordinal, exact bound target, original authorization/epoch, physical source activation and ordered source-history anchors. Crash before L spends the opportunity. Crash with an unrecorded response permits the next opportunity only under a fresh current gate. Exhaustion supplies local refusal without a snapshot.
3. A read observation denotes the first durable terminal candidate for its logical query. Authenticate the successful response strictly against that ordinal and its complete bound query. A retained error or absence also terminates the logical query. A new logical query can refresh and has its own debit/key. The bounded experiment has at most two logical queries per history and two physical opportunities per query. A single `Run` and one exclusive Store owner prohibit overlapping physical ordinals of the same query in this profile. Equivalent duplicate completion is idempotent. A non-equivalent second physical completion must remain visible as a conflict, never replace the original result. An unavailable or malformed endpoint offers no world evidence.
4. In one transaction retain the query's authentic response/candidate and its typed outcome, adoption decision/proof, and any new original result. On a validated found snapshot, read authority alone gives `denied`, a raw original gives `evidence_only`, and a non-success counter policy refuses reconstruction. An existing original candidate always remains immutable; a found snapshot gives additional knowledge only. When the original result is genuinely missing and adoption is authorized under the exact success contract, retain a distinct tagged `AdapterResult` identifying original operation and authorizing query/ordinal/proof, with the original candidate empty and no fabricated return metadata. Derive `{mutation,total}` from the one original receipt and the typed success envelope from the frozen schema. Bind the two result facts to composition ordering, append no original attempt/reservation/charge, and make `adopted=true` selectable only through that committed query result. Each separate resolver retains its own provenance. An equivalent later receipt can attest the same application without duplicate original result or debit; incompatible evidence stays explicitly classified.
5. Use the standard local accounting paths to settle original and resolver once. Include any original settlement owed by a successful import in the resolver dispatch lifetime before H. Recovery/Q for the resolver must finish both locally even if no worker survived or the resolver has closed. A genuine local SQLite failure is sticky for the source whose accounting failed. Read-only denied adoption is a completed policy decision. Crossing the after-commit/pre-settlement barrier must demonstrate a genuine recoverable prefix. Publication and ordinary selection remain their pre-existing independent transitions.
6. At replay/open independently derive the trusted target again from immutable original intent, attempt, authorization, grant, schemas, exact wire/ledger and query identities. Require a gap-free bounded ordinal sequence, authentic matched snapshot (if one was actually obtained), first durable terminal identity, bidirectional proof/result edges and the frozen handling disposition. Bind revocation and current source eligibility at each ordinal using retained historical anchors. Require original immutable candidate preservation or an explicitly tagged reconstructed result including its query proof. Replay cannot validate an external truth the endpoint did not guarantee; it can validate retained provenance, transport bytes and consistency without I/O. Neither historical Stores nor mutation adapters gain read-retry eligibility. Inspection includes the V5 tables and both result kinds.

## Gate and falsifiers

Before executable work, demonstrate the public construction actually reaches the target handoff and that the final consumer has a real ordinary visibility channel. As of source reconnaissance `retainTemplate` accepts only one caller boundary for a dynamic invocation, and captures that boundary's outgoing message as an invocation reply. Its readiness can depend on the missing original outcome. Treat a circular wait here as a genuine constructor obstruction. Independent review must address it before claiming a realizable principal plan.

Directed controls must distinguish digesting a preparation versus the wire, losing a read result versus retaining a negative, read-only grant versus import, adoption versus an actual original POST return, and existing failure versus later application knowledge. Verify late resolver closure, real sticky accounting failures, successor settlement, duplicate provenance and a genuine conflict. Recheck all version-dependent hooks and follow rediscovered interfaces or rejected designs with explicit revisions.
