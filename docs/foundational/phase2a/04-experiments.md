# What the executor and the endpoint actually did

## Cancellation by path

Every closure in the authority matrix targets the named, provisioned, generation-one subject using a distinct controller with a revision-one lifecycle grant. Manual schedules commit the source's original Emit, optionally call public AuthorizeIntent to completion, then commit and decide the controller's original operation before starting Run. The worker-held schedules use Run and ordinary input admission to wake the controller. Its accepted lifecycle decision commits while the worker or endpoint is held. Open-to-cancelled and the retirement flag are read back before release. Every experiment used an independent loopback process.

The root-only denial illustrates why consumer status needs its program context. The raw fixture binds only total from the receipt envelope and reaches succeeded with total zero after a denied reservation. Its sibling adapter program checks valid and fails on the normalized denial. Neither program exit by itself is a world observation.

Two A5 companions exercise both withheld paths with the actual source closed. The non-idempotent raw service applies and then drops the response. The adapter applies and returns an unknown candidate. After the first Run returns without a result, the operator commits CancelRun on the still-open original source. For the physical-order falsifier, take an authority record with cut=worker. The original reservation and allowed decision already exist at held. The world then has no contacts or applications. ## Same-record crash pairs

For each route, a closed provision is copied twice before either executor starts. Two initially empty endpoint databases serve the exact same address sequentially. Each endpoint stays up through its own executor crash, recovery and replay. U0 holds the sole worker before transport. U1 holds it after obtaining the genuine result but before retaining it. Signal exit and fresh-process Open are required. The comparison is between the cuts at recovery, allowing later contact with a capable endpoint.

|Route|Cut|Before kill: POSTs / applications|Recovery POSTs|Final applications / result rows|Ordinary consumer|
|---|---|---:|---:|---:|---|
|Raw idempotent|U0|0 / 0|1|1 / 1|Selects total 5, succeeds|
|Raw idempotent|U1|1 / 1|1|1 / 1|Selects original total 5, succeeds|
|Raw non-idempotent|U0|0 / 0|0|0 / 0|Open at original receive|
|Raw non-idempotent|U1|1 / 1|0|1 / 0|Open at original receive|
|Controlled adapter, idempotent endpoint|U0|0 / 0|0|0 / 0|Open at original Await|
|Controlled adapter, idempotent endpoint|U1|1 / 1|0|1 / 0|Open at original Await|

Each branch has one original logical effect and allowed reservation. These standalone clients incur no composition debit. The matched local tables retain the same namespace, source, sequence, authorization, request bytes, target, projections, original epoch and missing-result state within each pair. No renaming is used. Physical launch counts in these profiles follow the sole worker, one HTTP call per invocation and one matching ingress per call; the pre-call U0 worker cannot have called out. General packet loss need not have matching ingress.

Without a decisive observation and with an endpoint where repetition may apply again, deciding to repeat from this cut risks a second application in U1. Withholding leaves U0 without the first application or receipt. Fabricating success is false in U0. This is the information obstruction for the stated original request and endpoint capabilities. The adapter's different behavior at the idempotent service is an implementation restriction. The raw idempotent route demonstrates genuine useful completion under a declared stronger capability.

## Known cuts and negative controls

* At the raw and adapter post-record/pre-settlement cuts the result exists with no settlement. After recovery, settlement inserts the observation and a live consumer selects it. Killing after settlement but before selection also resumes through the retained observation. Neither case needs an extra world application. Adapter recording already had an observation seam. Raw uses one additional passive seam after the receipt transaction has committed and unlocked. A missing result after SIGKILL differs from a real error returned to a surviving worker.
* The controlled service commits before closing its connection without a response. The guarded adapter source consumes valid=false with zero/default result fields. The adapter's retained Candidate.Response describes the failed HTTP exchange, and the operation drops out of UnknownAdapters. The raw external route does not store an unsuccessful adapter candidate. The oracle sees a committed mutation. In the deliberately selected-error variant the candidate retains an actual validated receipt in its raw response; under the fixture contract a host inspecting those bytes can establish the historical application even though the ordinary typed value is invalid. A returned unknown candidate is discarded and leaves no result. See the [ordinary parent boundary](05-parent-boundary.md).
* Restarting the endpoint over the original ledger preserves the original result for its key. An altered same-key request gets 409. A new-key request mutates the resource again. A later duplicate of the original returns its original total 5 while the resource total is 10. For the five calls, the endpoint has five ingresses, four valid contacts, two applications. A separate genuine lifecycle Retry uses an eligible unscoped source with RetryCancelled set. Generation 2 repeats the same delta under a new original operation/key. Both apply. The member Retry guard in DecideLifecycle returns invocation_retry_unsupported.
* The recorder-level control offers an incorrect key and a contradictory payload alongside the first retained adapter result. It inspects the original after each refusal and archives both proposed candidates in the inherited/recorder command records. This is a private recorder test, never a capability supplied to the program. Wrong raw receipt correlation is covered by the existing late-receipt/forgery control.
