ALAN Phase 2D — Effectful composition, stable evidence, and recovery costs
Assignment
Goal: Establish or falsify a restricted composition-and-recovery rule for two original external operations sharing a controlled ledger, alongside a legal Series 1 pure owning tree. Ordinary consumers must use stable, correctly correlated evidence, preserve each original interaction, and account for the costs and lifetime conditions of recovery.

Architecture: One static owning caller invokes two issuing children and a pure subtree T. Each issuer has an exact identity handoff to that caller. Two separately rooted ordinary resolvers have exact read/adopt grants for their respective originals. Both originals use the same honest persistent counter ledger. The caller joins actual original invocation outcomes, authentic resolver reports, and the pure-tree outcome. All communication remains ordinary; the new construction support is limited to two explicitly provisioned handoff edges.

Tech stack: Existing Go, public author/runtime/effects/schema APIs, schema-5 reconciliation, ledger format 2, SQLite, actual process/barrier fixtures, independent finite models and Python audits, and the Markdown/LaTeX manuscript. Use the repository's pinned toolchain and dependencies after verifying them.

2. Findings that determine this experiment
Event-specific adoption is not a stable completion predicate
The unchanged Phase 2C resolver forwards its final query only. Query 1 may adopt the original; query 2 then reports an equivalent duplicate with adopted=false. The unchanged parent rejects that report even though the original has already settled. Preserve this exact example and its negative history. The per-query adopted field is truthful; do not redefine it to mean that someone previously adopted.

The same parent also checks mutation == 1 and total == 1. Those assumptions describe its fresh one-operation world. Two operations on a shared counter can both be correct while their receipt numbers and totals differ. A new consumer needs a declared per-original evidence policy.
The existing example is not an arbitrarily nestable effectful component
Phase 2C's identity-handoff template is outside Series 1's closed-template grammar. It supports one exact static caller, invocation sequence, caller port and entry port, with only one handoff template per deployment. The current binder selects one matching template and returns after binding it. Existing receipt grants support multiple exact targets, but resolver generations are fixed provisioned identities.

Authorize the smallest explicitly versioned extension for two exact handoff edges from one static caller. Preserve v1 behavior and old artifacts. Do not add dynamic grant delegation, arbitrary external peers, recursive effectful templates, or a general communication subsystem. A genuine two-edge public construction must pass before the principal model/campaign is frozen.
Capacity, local completion, and world application are separate
A potentially decisive schedule holds original L's worker in the only physical slot while original R's issuer commits its request, completes the identity handshake, and terminates before its own dispatch admission. Phase 2B then prevents a fresh exposure. Sufficient semantic invocation/effect allowance would not restore the missing application. Attempt this history concretely; do not describe it as an observed Phase 2D result before running it.

A second boundary concerns final report ACKs. The parent can send an ordinary ACK and terminate before its first authorization under an admissible public-driver schedule. The resolver can remain waiting despite a correct parent decision. General eventual service does not guarantee authorization before source closure. Whole-deployment completion needs a stronger, source-justified scheduling condition.
3. Frozen target topology and public contract
Use the explicit family F(T): a fixed static caller P owns issuer invocations L and R and a closed pure subtree T. The two designated resolvers are separate static resource roots, outside the revoked issuer scopes. Commit both issuer invocations at fixed sequences before blocking on handoff; commit the pure-tree invocation before its first selection. Keep each original locator stable across A/B choices inside T.

The original effects use the controlled adapter success policy, exact wire/schema, one immutable key each, and one shared ledger. Prefer distinct supported deltas 1 and 2 to make incorrect role matching visible; also include equal-payload distinct-original controls. No new business operation, generation Retry, compensation, key seal or endpoint fencing is introduced by reconciliation.

For each role the caller must separately retain its authentic handoff identity, original handle and selected envelope, genuine application evidence, and relevant original/query classifications. The report source, obligation, original target and evidence must match that role. Equal business values, receipt totals or program identities cannot identify an occurrence.

Define a new bounded ordinary resolver report. It should retain the first actually selected compatible found receipt and its originating logical query identity, while recording later query outcomes separately. Request identities can already cross typed string boundaries. Do not invent a physical ordinal or snapshot field that authored code cannot see; deeper provenance can remain in the actual runtime observation and audit mapping.

The new policy must handle:
- Found/adopted followed by found/duplicate without losing the earlier evidence.
- Found followed by a genuinely retained later query transport error, while preserving both the positive evidence and the later unsuccessful query.
- A prior ordinary original result classified existing, preserving that exact original outcome.
- Absence, refusal, exhaustion and unavailable lookup without inventing application or final nonexecution.
- Incompatible positive evidence or an explicit conflict without silently choosing a convenient receipt. Retain the historical witness and expose the conflict.
Do not turn found alone into success. The caller must actually consume its required original invocation outcome as well as the report. A read-only resolver can know application while the missing original still prevents publication. Raw and unsupported policies remain outside the positive reconstruction domain.

Use one designated sequential resolver per original in the main completion theorem. This supplies an important settlement invariant: an adopted query's ordinary Await occurs after its original and query settlement; a later sequential duplicate does not undo that work. A fresh read against an existing result must satisfy the actual original-drain gate. Separately audit original settlement, publication and selection. Publication alone is not a settlement certificate.

Include a competing-adopter boundary case. Two queries admitted before the first import can race: the duplicate may settle while the importing resolver still owes original settlement. A duplicate report and original publication then do not certify that every required settlement has finished. Either establish the stronger premise explicitly in that case or limit its claim to the facts actually observed. Do not add a new settlement API merely to hide this distinction.

The caller must join all required work before its final success/diagnosis branch. A pure-tree diagnosis does not undo either business mutation. A genuinely pending pure leaf can coexist with applied effects, retained reports and resolvers awaiting ACK. Specify that frontier exactly, including which original outcomes have been selected and which reports remain delivered or unconsumed. Pending is not a timeout classification.
4. Three claims to establish separately
4.1 Prefix safety
For every declared legal public-driver prefix, prove or find a counterexample to: no query-induced business mutation; no cross-role adoption/acceptance; preservation of original identities, selected interactions and publications; no invented application or final negative; honest evidence retention; and conservation of actual semantic debits and physical-read expenditure.

Model parent decision, parent root publication, original settlement, each resolver's terminal state, and local quiescence as different facts. A valid parent decision may coexist with an open resolver in the adverse ACK schedule. This does not permit a false all-roots-complete claim.
4.2 Restricted composition and recovery relation
Define an explicit independently specified reference protocol and a relation from the retained implementation histories to it. Include both original application events, shared-ledger order, query snapshots, owner loss, durable opportunity expenditure, direct/reconciled results, settlements, reports, actual selections and termination. Give the relation's domain, direction, observable projection, allowed stuttering and progress premises before enumerating results.

Use a visible cost vector, at least (invocations, created runs, mutation-effect debits, logical-read debits, physical-read opportunities, mutation contacts, lookup contacts, business applications). Track depth, per-root and global physical capacity, representation limits and remaining allowances separately. An opportunity spent before contact remains spent. Costs cannot reset on Open or disappear because a business decision matches.

Recovery can consume another read ordinal, obtain a later snapshot and produce different provenance/adoption classifications. Do not claim equality of the complete uninterrupted and recovered histories. A business-outcome comparison may project specified role classifications, original envelopes and matching receipt fields, but must be labeled as that projection. Preserve the complete public results and costs alongside it; do not call it full observational equivalence.

For equal per-role receipt values, couple the original application trace and order on the same declared ledger. Reverse the two application orders as a real control: the final total may agree while individual receipt sequence/total values differ. The relation must preserve correspondence to the actual world trace rather than infer equivalence from the final scalar total. Query snapshot order may differ under the declared recovery rule; retained negatives remain historical observations.

State a source-level composition argument for F(T) over legal, representable Series 1 trees and every independent A/B placement, using the original requests and hypotheses. Reuse the established pure-tree theorem only after proving its new frame: disjoint identities/ports, stable grants, open owning caller, sufficient common resources, and service of its prerequisites. The new handoff grammar and effectful surrounding context are additional obligations. If only a fixed concrete instance can be justified, label the result bounded and leave the parametric rule open.
4.3 Conditional useful completion
The positive progress premises must be independently checkable. They include unique original applications visible before the reads on which progress relies, an intact honest ledger, genuine original R/Q, exact resolver read/adopt authority, live recipients, adequate remaining allowances, successful accounting, and actual service. Two physical opportunities tolerate at most one pre-retention loss per logical query in the corresponding positive failure domain. Mere eventual application does not ensure that one of a finite number of reads observes it.

Derive the new guard's success from those premises and its actual program. Do not assume “the final report is the one that adopts” or “the parent guard succeeds.” For original dispatch, establish the pre-admission/lifetime and capacity premise separately; a receipt theorem cannot make an unlaunched request apply.

Qualify all-roots completion by an actual unchanged-`Store.Run` service lemma. The runner currently services one pending internal delivery before committing one ready instruction each turn. A useful proposed schedule has the caller consume all required original outcomes, both resolver reports and the completed pure-tree outcome before sending final ACKs. Prove/check that each new ACK is the sole pending internal delivery at the relevant turn and is authorized/admitted/bookkept while the caller remains open. Both resolvers stay open until ACK selection. Establish the fresh-owner counterpart after a crash between ACK commit and service.

The sole-pending predicate must come from actual retained program/control state and the runner source. It cannot be an unexplained fairness assumption. If extra pending work invalidates it, retain that counterexample and narrow the completion theorem. Do not modify the scheduler or add an ACK-of-ACK chain to force all-schedule completion.
5. Resource and construction discipline
Series 1 defines b(Leaf)=4, h(Leaf)=3, with one additional slot/depth at Relay and b(Fork)=1+b(L)+b(R). The entry of T is included in b(T); the static caller is excluded. For two singleton issuing children, start the new frame from I/R at least b(T)+2, depth at least max(h(T),1), and two original semantic effect debits. Verify these bounds from actual retained construction, including all extra control work and representation limits.

For a two-leaf pure fork the common original bound is nine dynamic slots, giving eleven with the two issuers. Actual AA and BB spending can still differ. Preserve that distinction. Resolver roots each need their actual logical-read allowance, ordinarily at most two, and the existing two durable physical opportunities per query. Extra actors in controls have separate visible permissions and costs.

Use a placement whose actual demand reaches the tested resource bound for a one-less refusal control, such as the all-B fork for dynamic slots. One below a common upper bound need not refuse an AA placement that lawfully spends less. Freeze the relevant remaining demand and causal schedule before execution.

Choose both global and per-root physical capacity explicitly. Use a sufficiently provisioned positive original-dispatch profile, ordinarily capacity two while both original workers can be held, and validate both admissions/ingresses before the relevant closures. Keep capacity one as a real adverse experiment. Increasing capacity must not be presented as restoring an unlimited scheduling theorem.

No old Store, template or grant gains authority from this phase. The new construction profile must identify exact invocation locators, caller ports, entry ports, obligations, schemas and directions. Reject duplicate/ambiguous bindings and alias collisions, and install permissions only for the matching actual admissions. Preserve v1 and the Series 1 closed-template bytes. Version the actual changed representation/semantics deliberately; do not choose a schema bump or migration before checking what is necessary.
