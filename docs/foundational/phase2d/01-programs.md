# F(T) at the program boundary

The constructor retains three static runs. The caller’s first three commits invoke L, R and T. Each issuer consumes its bound entry request at sequence 1 and emits its only mutation at sequence 2. The two handoff locators use the caller’s invocation sequences 1 and 2, their respective template and the `source` entry member. The separately rooted `resolver_l` and `resolver_r` receive the actual IDs over the corresponding ordinary relay, echo them, and wait for empty local service inputs. P checks each relay echo and sends it on the matching identity port. Both sources consume their own ACK. The pre-query state and each resolver’s actual read/adopt grant are independently inspectable. | Guard operand | Program source and meaning |
| --- | --- |
| `l_target`, `r_target` | P's two ordinary identity receives. P matches later reports and original replies against the appropriate received ID and requires distinct occurrences, including when both deltas are one. |
| `*_source_status/reason/present`, `*_issued_target`, `*_observed/interaction/valid/mutation/total` | Captured invocation outcome selected by P. An issuance-only source sends its truthful issuance marker before its identity send and selects no adapter result. An observing source first completes the handoff, actually Awaits its own original result, and puts those selected fields in its subsequent bound reply. A `transport_error` branch requires failed/member_failed, false validity and normalized zeros. A direct validated branch checks its selected receipt numbers against the independent resolver report. Missing optional reply fields are never read on the absent path. |
| Resolver `witness_*`, `conflict` | A valid found observation with the designated target can establish the first witness. Its query ID crosses a declared single-row string collection; it remains data. Subsequent matching receipts leave the first witness intact. A differing target, mutation or total, an explicit snapshot conflict or a conflicting import makes the conflict sticky. An unsuccessful later observation retains its own normalized values and cannot erase the first witness. |
| `*_report_*` | A role-specific ordinary receive. The closed report carries its designated target, query count, first witness, conflict flag and both logical queries’ IDs, observed status/target/receipt, validity, disposition, adoption reason and adopted flag. The unused second slot has empty ID and typed defaults. P verifies its witness against the referenced selected observation, including exact value and adoption class. A supported evidence branch accepts adopted, duplicate or existing. Read-only found evidence alone cannot discharge a missing original. No program reads a physical ordinal or remote snapshot number. |
| Shared receipt pair | P accepts either legal application order on the declared initially zero ledger. The first application has mutation 1 and total equal to its own delta. The other has mutation 2 and total equal to the sum. Authentic role evidence from another operation with the same business value is insufficient. |
| `tree_*` | P selects T’s actual original envelope and typed product. It checks each literal leaf ID, the returned classification, the bounded answer list, each complement and the aggregate status/reason. A present checked diagnosis is retained separately from the two business facts. An absent pure envelope is classified invalid before optional fields are consulted. |

Selection order is L invocation, R invocation, T invocation, L report, R report. A pending T leaves both original invocation selections possible and both resolver reports unconsumed even after the reports are admitted. A missing L prevents every subsequent required selection. After all five selections, P records `applied`, `applied_tree_diagnosed` or `invalid_evidence`, emits the two ordinary final ACKs, and takes its corresponding End. Each resolver selects its own matching ACK before End. The private decision and ACK emission alone do not establish whole-deployment completion. [Resolver](../../../examples/effectfulcomposition/resolver.go) · [Parent](../../../examples/effectfulcomposition/parent.go)

The public tree value seals its template, depth, slot count and leaf paths. Its constructors call the original Leaf, Relay and Fork builders. The two-issuer frame adds two dynamic slots and two possible mutation debits; its parent root sets capacity independently of each resolver’s single slot. Input validation enforces the Series 1 closed record, mode enum, IDs in {1,2} and Boolean integer values. A separate test compared actual nested template bundle bytes with direct Series 1 construction. [Tree](../../../examples/effectfulcomposition/tree.go) · [Byte comparison](../../../examples/effectfulcomposition/deployment_test.go)

Two actual malformed-join attempts informed this construction. The v1 paired handoff was rejected as specified in the binding witness. In a first stable-witness design, a branch assigned a retained Request handle to a register initialized as a plain string. At the report Send, the compiler rejected the merged register as not definitely available. The negative test preserves that rejection. Passing the genuine ID through the declared bounded collection allowed both branches to retain an ordinary string. It supplied no new right to Await. Additional controls actually selected failed, absent issuer and tree envelopes and exercised the same guard instructions through terminal classification and replay.
