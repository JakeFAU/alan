# Reading the composed histories

The primary deployment has one SQLite Store, one durable counter ledger and three static roots. P's first two invoked singleton children issue the business operations; its third invocation is the actual Series 1 subtree. The public consumer creates, services and inspects this deployment through the public facade. An integration-test owner can stop at a named runtime boundary, and the lookup/mutation relay can independently delay a real packet, forward its exact bytes, lose a returned response or hold delivery. The endpoint process commits the business state and supplies receipts. A host start/refresh input is an empty scheduling signal. It contains neither a receipt nor an original ID. ## Causal cuts in the principal process corpus

* **forward, reverse, equal-reverse.** Hold the original executor before its first issuer End, observe the distinct admitted packets and commit the ledger applications in the requested role order. Both issuing members select their genuine handoff echoes and End. SIGKILL loses the outstanding returns before the original results are recorded. Each grant is exercised after reopening. Compare receipts role by role, including when the two deltas agree. Unrelated runs have different namespaces/keys. Only the explicit matched fork below couples original bytes across branches.
* **stable-duplicate, stable-error, mixed.** After a successful first R read, trigger a distinct logical refresh. The duplicate has its own truthful false adopted flag. For stable-error the real upstream lookup succeeds and its response is dropped at the relay, so the retained transport interaction is unsuccessful. In mixed, the original L response is dropped while L is still observing. The child actually consumes transport_error, sends its issuance envelope and fails. The later L read finds an existing result, and the R read reconstructs its missing supported result. P retains L's original failure under its applied-after-failure classification. Compare the historical strict caller in the separately rerun Phase 2C refresh control.
* **read-only, finite-reads, retained-absence, lost-absence.** Hold an original at true endpoint ingress when the schedule needs to observe absence before later application. The resource server may finish its already accepted operation independently of the dead executor. A retained absence persists under its logical ID; refresh requires a new logical query. Losing the negative response before retention can spend the next physical ordinal on a new snapshot under the same logical query. Exhausting the selected negatives first leaves the parent waiting at R even after later application. The read-only control legitimately knows application but lacks the permission to reconstruct R's original.
* **capacity-one, spent.** While L occupies the sole global/original-root slot, R has committed its request, exchanged its identity and ended before first exposure. Inspect its first authorization/refusal and actual zero R contacts. Neither semantic headroom nor an ID supplies physical service. The spent control cuts each of two physical opportunities after admission but before endpoint contact. Both ordinal rows remain charged under the same logical request after Open, despite zero R lookups.
* **pre-retention, atomic, original-selected.** Stop a new owner after the real R response but before recording, after atomic import but before the remaining settlements, or immediately after P selects L's original. In the last case R is still missing and P has not consumed L's report. Earlier committed facts survive fresh ownership. Compare ordinal/lookup counts before and after each cut to distinguish a new lookup from strictly local accounting.
* **auto-acks, fresh-ack, manual-ack.** Capture the actual committed ACK and census every eligible internal delivery kind. The automatic case continues the owner through both cuts. The fresh case takes an acknowledged SIGKILL after the last committed Send and reopens. The manual case uses the same live owner's ordinary Commit after stopping the automatic runner at the durable cut. P can End before the R ACK's first permission. Compare actual subsequent first permission, receipt at the recipient, selection, terminal state and each root's publication. The branch decision alone would classify all three cases identically.
* **paired.** Fork matching cold Store/ledger backups after both original applications and one completed lookup. The right logical service input already exists. Both continuations use these exact original keys, wire, ordered applications and persisted endpoint identity; the continuation processes themselves have different PIDs. One completes R's read normally. The other loses the real R response before retention and reopens. Compare the serialized business projection and original applications against full histories including new physical snapshots, PIDs and ordinals. “Continuous” denotes absence of this additional loss *after* the common prefix. ## Pure-tree grid and deliberate controls

Each grid case runs the complete fixed caller on the same Store as T. Four independent A/B assignments cross four left and four right modes. Literal values are left zero and right one. The AA/AB rows deliberately reuse ID one on both sides. The BA/BB rows distinguish IDs one and two. A legal completed diagnosis must keep both effects and the actual failing or missing-reply leaf. A pending T must put P at its T Await with both earlier original outcomes selected and both independently delivered reports unconsumed. Check the leaf PCs, own original operation, first unpublished child and unselected available sibling at every nested fork. The historical pure occurrence walker handles the actual embedded subtree. A separate raw decoder rechecks the grid without importing the campaign's grading code.

Three relay variants put the wrapper above the fork or on a single side. In the slow-read case T is still open when a real lookup occupies the sole available physical slot. The fixture services its staged instructions and observes a pure terminal/publication while the lookup is still held. The positive original-dispatch prefix used capacity two. Four all-B deficit cases remove one invocation, created run, depth level or original effect debit separately. Inspect the actual admission and debt records for the refusal. These cases do not extrapolate from one below the common bound on a less expensive A placement. ## Reading a case without trusting its verdict

A backup ending in `-local.sqlite.gz` is a cold copy taken through SQLite's backup API. Its matching `-world.sqlite.gz` is the independent endpoint snapshot. A checkpoint links both to the process events and the journal prefix at that cut. The process trace records actual PID, binary identity, argv, environment overrides, acknowledged selectors and exit status. SIGKILL must have the matching negative wait status. Some adversarial histories instead use separate descriptor and journal files per checkpoint. The experiment does not establish an unrecorded volatile event from replay.

Start with the three actual P invocation operations. Derive L/R member and original Request keys under the Store namespace. Check the authority grant, selected handoff and echo, exact original request wire, endpoint application rows, each logical read/ordinal snapshot, result/proof linkage, independent settlements and finally the actual selections and role registers. Compare every charge with the distinct root that paid it. Depositing an observation in an inbox is a different event from the recipient's later selection. The final offline public Replay runs on a copy; before/after hashes of the DB and endpoint journal identify the zero-contact window. The raw auditor separately mutates disposable copies, including a rehashed false status and a swapped authentic receipt, and exercises actual public Replay.
