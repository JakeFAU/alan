## Complete outgoing check

For each declared profile I checked the fixed route, membership, selected authority, permitted operator, reply policy, restart and duplicate/peer flags against an independent manifest. ID zero must exactly match the initial state, including original key, grant, request and debit. At every row the checker derives the observer's answer, enumerates all permitted labels, and compares **every field** of each labelled destination. All destinations must exist, labels and state representations must be unique, and every row must be reachable. The final census was 908 states, 1,446 edges and 66 sinks. [Executed comparison and mutations](commands/model-outgoing-final.json.gz)

Action ownership matters for interpreting sinks. There were 720 local execution edges, 334 closure-driver edges, 93 host Q choices, 57 shutdown/crash/open choices and 242 independent endpoint edges. The closure-driver category includes an ordinary End/Failure commit and publication where the profile selects that boundary. Success of the graph comparison does not imply a single Run invocation controls this order. In particular, another public driver must win R while automatic Run itself is held before A. After A the worker can be held independently. Both the raw and adapter profiles admit R and the local peer commit with the worker still short of L. A positive Q requires service through accounting. There is no positive wait observation at a mere deadline. [Executed comparison](commands/model-outgoing-final.json.gz) · [Live schedules](../03-live-experiments.md)
