# Phase 1H bounded adaptive composition contract

Status: proposed application contract for independent review before implementation. Source basis is reviewed Phase 1G commit `4550e0f4ba4c57cae8e84d1afe9fbf47e16786d8`; the controller records current main and PR dependency separately. This document makes no implementation or qualification claim. Final location: `docs/foundational/phase1h/01-adaptive-contract.md`.

## Intent and scope

An ordinary reusable retained application accepts typed seed work after initialization, consumes a complete round's outcomes, derives the next ordered frontier from those outcomes, and repeats within persisted application limits. It uses one adaptive member at the same invocation depth through all rounds. Direct and nested deployment use the identical adaptive artifact and its identical public schemas. No scheduler, runtime opcode, persistence migration, privileged coordinator, or host-side frontier builder is planned.

Existing interfaces actually inspected: `author.Definition` with `Values`, `Collections`, `Invocations`, `Ports`, and `Steps`; `author.ForEach(collection Expr, bindings map[string]string, body ...Step)`; `Set`, integer `Add`, `Offset`, `IfEqual`, forward `Goto`; `Invoke(pending, template string, values, updates map[string]Expr)`; `AwaitInvocation(template,pending string, InvocationOutcomeBindings{Status,Reason,ResponsePresent,Response})`; `Request`/`Await`; `author.NewTemplate(Application,entryMember,entryPort)`; `Template.Schemas()`; `schema.Field`, `schema.List`, and `schema.Record`. `compose.New(leaf, Options)` provides the existing all-invokes-before-collect pattern, but invoking a collection per round would exceed the nested depth profile. Reuse its ordinary step pattern inside the adaptive artifact instead.

## Identity and finite schemas

Work IDs are application integers, distinct from runtime operation strings. Seed IDs must be in the application profile's finite domain 1..8, validated by ordinary iteration/equality before any leaf invocation. This is an application restriction, not a new runtime constraint. Child slot 1 has ID `3*parent+1`; slot 2 has ID `3*parent+2`. Observation 1 uses slot 1/edge `check`; observation 2 uses slot 1/edge `left`, then slot 2/edge `right`. `Add` computes the multiplication through two additions. Parent and edge are explicit provenance; a human alias such as `gamma/left/check` is only an oracle annotation. Including the unperformed frontier beyond round three, maximum ID is 242, so the checked input domain prevents arithmetic overflow.

There is no public string concatenation operation. A generic concatenation extension is unnecessary for this profile. Alternative canonical structured lineage IDs would support arbitrary seed strings using bounded lists but increase schema and equality work. Reserving a fixture-specific name schedule or constructing frontiers in Go is rejected. If arbitrary runtime string-derived IDs become required, first retain an external-module compile counterexample using `Add(Var("id"),String("/check"))`, which fails with `add requires int`; compare structured lineage with a separately reviewed bounded concat proposal. Do not implement such a repair as part of this design.

All records are closed. Every list has `MaxBytes:262144`; all nested schemas stay within existing nesting 8, fields 4096, and aggregate value 1 MiB limits. IDs/counts/observations are `int`; presence/completion are `bool`; operation/reason strings are bounded at 4096 bytes, statuses at 32, edges at 8, stop reasons at 32. Integer identity lists omit `UniqueKey` because it accepts only string keys. Ordinary nested iteration performs duplicate validation.

Scalar public request:

- `seeds`: list, MaxItems 8, element `{work_id:int,value:int}`.
- `max_rounds:int`: application membership validation in `{1,2,3}`.
- `max_work:int`: application membership validation in `{1,2,3,4,5,6,7,8}`.

Scalar leaf request `{value:int}`, result `{observation:int}`. Controlled scalar leaf performs ordinary `Request`/`Await` to one controlled capability and forwards a valid typed observation; an invalid/known failed effect ends its invocation unsuccessfully. A pure scalar leaf returning its input through ordinary Send is also available for recovery boundaries that must not create external uncertainty.

Frontier row `{work_id:int,parent_id:int,edge:string,round:int,value:int}`. Seeds become parent 0/edge `seed`/round 1. Candidate and remaining lists have MaxItems 16, because eight completed items can produce sixteen unperformed children. This increases no runtime limit: eight is the application work ceiling, whereas the existing generic schema allows 10,000 list records. No work is admitted above eight. Handles and total results have MaxItems 8. A result row includes every frontier field plus `{operation:string,status:string,reason:string,responses:list}`; responses is MaxItems 1 with the leaf's exact public result schema. Absence is an empty list, never a default response.

Application reply `{complete:bool,stop_reason:string,rounds:int,work_count:int,results:list,remaining:list}`. Results preserve round order then frontier order. `rounds` counts fully consumed round barriers; `work_count` counts items in application-admitted frontiers, including a later runtime-denied Invoke. Runtime admission/run/effect charges are separate. `remaining` is the entire ordered derived but unperformed frontier; it may contain duplicate identities when reporting invalid input, so it has no uniqueness schema constraint.

Evidence mode replaces scalar `value` with `question:string(MaxBytes4096)` and uses the unchanged `evidence.RequestSchema()` and `evidence.ResultSchema()` for the directly invoked two-member leaf. Both modes retain exact mode-specific response schemas. There is no adapter invocation between adaptive and evidence. Ordinary application steps map public disposition `answer`/`no_match` to zero children, `clarification` to one `check`, and `insufficient_evidence` to two `left/right`; child questions copy the current question. `budget_exhausted` or an otherwise invalid succeeded response is `invalid_observation`; known failed invocation takes the failure rule first. The compact controlled case returns clarification then answer, with a separate known-failed helper case. No prompt, corpus, grade or helper policy changes.

## Round algorithm and application stopping

Persist the received request and limits. Validate scalar profile values and the complete seed identity set before any item work; invalid scalar profile/domain values return incomplete `invalid_request`. Duplicate seed IDs return `duplicate_work_id` with the full seed frontier and no leaf work, after profile/domain validation and before work-limit checking. Seed count above requested max_work returns `work_limit` with all seeds remaining and no item invocation. Empty valid seeds return exhausted, rounds 0/work_count 0.

One retained control list `{round:1},{round:2},{round:3}` drives `ForEach`; it does not unroll round bodies in Go. Each active iteration validates and admits the whole current frontier, creates all Invoke intents in frontier order while retaining handles, then awaits those original handles in the same order. Independent leaf execution still proceeds regardless of the consumption order. Append accepted outcomes to retained round evidence and the ordered total results. Only after every required outcome is known can the derivation pass run.

For every succeeded/present scalar result, observation 0 emits nothing; observation 1 emits child `(3p+1,0,check)`; observation 2 emits `(3p+1,1,left)` then `(3p+2,0,right)`. Unsupported observations are explicit invalid observations. Derived payloads are actual-result-dependent; fixtures cannot choose frontiers. Continue building successful siblings' children even if another item has a known failure, to preserve the unperformed work honestly.

Preflight the whole candidate frontier before any next-round Invoke: compare every pair for duplicate IDs and every candidate against previously application-admitted IDs. Use a local counter/position to avoid self-comparison. Distinct IDs with equal payloads remain distinct. Retain duplicate flags and the full candidate list. Preflight requested work capacity with a trial counter: for each candidate, equality with max_work before increment flags overflow; no greater-than primitive is required.

After the complete barrier/derivation/preflight, choose exactly this precedence:

1. The first nonsuccess item in frontier order stops the application. Rejected `invocation_limit`/`created_run_limit` gives `root_budget_denied`; other nonsuccess gives `leaf_non_success`. Preserve all item statuses/reasons/responses.
2. Any succeeded missing/unsupported response gives `invalid_observation`.
3. Candidate duplicate against this frontier or history gives `duplicate_work_id`.
4. Empty candidate gives `exhausted`, complete true, even if a limit was reached exactly.
5. Candidate count would exceed remaining total allowance: `work_limit`, complete false.
6. Current round equals requested max_rounds: `round_limit`, complete false.
7. Otherwise retain the candidate as next frontier and continue. No prefix admission when the whole frontier does not fit.

Clear the declared one-row `decision` collection with Set(empty), then perform one ordinary Append whose row contains round, ordered candidate, chosen stop reason and complete flag. That Append marks the retained decision boundary after round evidence. Admission starts only after that commit. Individual subsequent Invoke commits atomically retain their pending operation identity. The normal durable history and ForEach residuals suffice; there is no new decision ledger. Re-execution resumes an unfinished instruction/cursor, never repeats completed external work to reconstruct an accepted decision.

Exhaustion and orderly work/round-limit replies end with `Success` at the protocol layer; bounded stops have complete false and explicit remaining. Invalid request, invalid observation, duplicate, known leaf non-success and root-budget denial Send the diagnostic reply then Failure. Wrappers faithfully forward presence, payload and status. Protocol success does not assert application exhaustion.

Unknown required work blocks Await/barrier and remains spent. It is never observation zero, known failure or replacement authorization. No success can bypass unresolved transitive obligations. Operator closure may prevent an application reply; callers then see the existing cancelled/abandoned/failed envelope plus retained partial evidence. Root/ancestor closure fences admissions and reservations; already accepted work and charges survive, and late evidence cannot reopen the decision. Run context cancellation alone is not logical cancellation.

## Resource accounting and recovery

Root depth 0; direct root→adaptive→leaf reaches depth 2; nested root→wrapper→adaptive→leaf reaches depth 3. The evidence helper's two members both occupy the leaf depth. For N application items that are all admitted, scalar direct/nested costs N+1/N+2 invocations and created runs, with at most N effect reservations. Evidence costs N+1/N+2 invocations, 2N+1/2N+2 runs and at most 3N effect reservations. At N=8 the nested maxima are 10/18/24; shared envelope remains 32/64/96, capacity 1 or 2. One static root run is reported separately as fixed provisioning cost. A rejected Invoke consumes no invocation/run charge; an unknown reserved external effect stays charged. Recovery cannot change request limits, create a new root, or raise persisted limits.

Qualification cuts acknowledge existing execution/invocation boundaries: (a) all round results consumed and decision committed, no next-round intent; (b) one or more next-round intents/admissions committed while others remain absent/pending; (c) some next-round results consumed while required siblings remain unfinished. Actually kill the process, inspect the acknowledged source identity, then fresh-process Open/Run and compare original operation IDs, decision inputs, partial results and charges. Completion cases use deterministic or unattempted controlled work so killing does not silently convert authorized uncertainty into a retry. Separate unknown cases remain pending after recovery with no repeated provider contact.

The independent fixture oracle checks primary frontiers `[1,2,3]`, `[7,10,11]`, `[31]` (7 leaves), paired `[1,2,3]`, `[7]` (4 leaves), same artifacts and initial payloads with only gamma's returned observation changed 2→0. Primary scalar charges are 8/9 enclosing-inclusive invocations/runs and 7 effects; paired 5/6 and 4. Check empty/all-zero seeds, duplicate/collision, out-of-order completion, limits, known failures, denied admissions, unknown outcomes, closure, and read-only replay with the existing OS isolation mechanism. An authentic faulty ordinary application runs the paired case, consumes gamma observation zero, then substitutes two before derivation. It must reach the decision/admission boundary and fail this unchanged oracle for admitting forbidden descendants while remaining runtime/replay-valid.
