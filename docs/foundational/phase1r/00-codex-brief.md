Separate a single-artifact check from certification of a candidate template and its reachable dependencies. - [ ] State the new theorem as a **restricted** implication. Start from a certified finite X and its original `Conf_N^σ(X) = (∃Rw. W_N^σ(X,Rw)) ∧ Progress_N(X)` for each of the event and fact readings of the boundary. This covers `{1,2} × {0,1} × {answer,fail,absent,pending}`. Take `T₀[X]=J[X]` and `Tₖ₊₁[X]=R[Tₖ[X]]`. Keep P's independent reference and O-policy premises. Use Q's legal environment at each finite k, with `I=R=k+4`, `E=0` and depth cap `k+3`. - [ ] Freeze discriminators and acceptance criteria before implementing the checker. ## Task 2 — Implement the smallest useful opaque-handle profile

- [ ] Add a research-only checker, provisionally under `research/nominal/`, callable on an artifact/template built with the existing public authoring API. Prefer checking retained bytes and their transitive bindings. If a source-level check is essential, show how its verdict is bound to the exact lowered bytes, initializer and executable instruction mapping. Existing programs continue to compile and run through the ordinary path. A certificate changes no runtime data or historical artifact.
- [ ] Freeze a small operand algebra. Literal data stay literal, even when a string happens to spell a valid operation ID. An original Invoke introduces a fresh `Handle[declaration]`. Permit only the operations whose proof is supplied, initially storage, copying, same-sort equality and matching original Await. Handle equality must preserve aliasing and distinguish different commits from the same declaration. A v1 checker may reject handle collections entirely. Ordinary application strings, records and lists must retain their ordinary meaning.
- [ ] Follow values through actual initialization, assignment/aliases, control-flow joins, loop and collection bindings, emit updates, request and outcome bindings, payloads and declared outputs. Prevent handle-to-data escapes and forged data-to-handle uses, including casts by serialization and stale register contents on absent responses. Check every reachable alternative or conservatively check all instructions. Reject unknown opcodes, mixed sorts and unchecked dependencies. A ban on one API spelling or one `Append` instruction is insufficient.
- [ ] Return an inspectable result bound to checker version, source/artifact identities and checked scope. Identify any separately supplied frame assumptions. A stale verdict must not transfer to changed code, initial data or a substituted helper. No new credential service, runtime token format, schema migration or change to legacy replay is needed.

## Task 3 — Prove what acceptance buys

- [ ] Define one growing, sort-preserving partial bijection on **structural** operation names, extending it consistently at paired fresh commitments. Hold application values, program constants, PCs, definedness and diagnoses fixed. Pair the old external root with the new resource root, and the old immediate caller with the actual relay caller separately. The old root and caller can coincide. A global permutation alone cannot split that alias.
- [ ] Prove the checker sound against the accepted retained instructions. Relate initial states. For each reachable pair show that every enabled private choice or step on either side has a corresponding step and related successor, including aliases, comparison outcomes, loops, blocked receives, real original-handle selection and absent bindings. Establish preservation **and reflection** of eligibility needed for progress. Keep every actual private step in the projection. A relation defined as “the branch is already invariant” does not discharge this task.
- [ ] Supply the remaining frame argument. Check actual parent/root catalogues, rebinding of declared ports, schema and generation, first authorization versus current admission, post-End bound replies, open waiting ancestors and settlement on failure. Translate physical depths/cap and prior charges together. After k relays and J are admitted the inner residual remains three, with only S acceptance representing q. Use Q's once-only slot bound without treating headroom as permission. Establish finite entry/return service, infinite private projections, finite projections with an erased suffix, and the exact quiescent pending boundary under the original continuous-eligibility assumption. Concrete byte, sequence, step and dispatch adequacy applies **in each frame**, including differently sized encodings.
- [ ] Reuse reviewed P/Q lemmas at their stated premises. Name precisely which missing hypothesis the certificate discharges and which remain independent. Have a reviewer try to produce an **accepted**, representation-sensitive artifact before accepting the theorem. An unsound acceptance is a checker counterexample. A counterexample to the restricted relay theorem additionally needs that candidate's actual original W and Progress, its legal translated frame, and a violated public guarantee.

## Task 4 — Make the two readings of the evidence distinguishable

| Fixture or attack | Required observation |
| --- | --- |
| Unchanged Phase 1Q probe | Ordinary execution still produces the two historical markers. The private operand checker rejects the handle-to-string escape at a precise point. Exercise the operand checker directly or use an otherwise admissible K1-shaped twin so rejection for root shape alone cannot pass this test. |
| Data-only twin | The same supported list, iteration and literal comparison on ordinary string data is accepted. Include a literal equal to a possible handle spelling. |
| Honest handle-using candidate | Check unchanged B and its actual helper, plus A as the no-helper control. Require a real handle-producing and handle-consuming positive case. If B is refused, preserve the reason and distinguish a v1 expressiveness limit from unsoundness. |
| Aliases and laundering | Test genuine copy/Await, alias equality if admitted, distinct fresh handles, wrong declaration, literal forgery, an indirect list or payload escape, and a branch join or reassignment that loses provenance. Use paired positive/negative controls with the same surrounding instructions. |
| Separate contracts | A spelling-insensitive candidate returning a wrong literal answer can pass the operand check and fail K1. Mutating a certified helper or initializer invalidates the earlier certificate. |

For the positive alias and fresh-handle cases, run the same accepted bytes with different actual operation spellings and fixed application literals. Predict the comparison result, enabled branch and selected original operation in each run before inspecting the records. The same terminal report can conceal a different private choice.

After the validator and proof pass independent review, run **one actual relocation experiment** through the public API. Use the same certified handle-using leaf/helper bytes in the canonical J frame and under one faithful diagnostic relay. Rebind the fixed O policy through the supported template API. Correlate original commitments, actual selected child observations and each caller's newly bound reply in the raw records. Compare literal reports and control decisions while allowing the raw identities to differ. Cover answer, failed-with-present-diagnosis, missing-reply-with-present-diagnosis, and the genuinely unpublished pending outcome. Freeze expectations and per-artifact operational bounds before running. Keep capacity one where supported. Report this as finite correspondence for those instances. Q's larger nested family campaign can be a later phase.

**Stopping rule.** If a checker accepts a spelling-sensitive case, preserve the smallest program and first divergent instruction, fix the checker or narrow its admitted syntax, and repeat the affected tests and review. If the correspondence, frame proof or public construction fails, deliver the exact failed obligation and independently supported result. Keep the original control and its observed behavior intact. Never obtain a pass by renaming application literals, running only the no-handle candidate, assuming all-depth conformance, or counting matching terminal outputs as a progress proof.
