## Recommended minimal contract and independent checking boundary

This is a proposal for Stage1 review, not a frozen approved contract. Choose and record the final variant before separate implementation authors begin.

### Pure positive profile Kp

Use request `{x:int, mode:int}` with `x` in `{0,1}` and mode in `{success,known_failure,absent}` encoded as finite integers. Result has `{y:int}`. In success mode require terminal succeeded, response present, and `y` in `{x,x+1}`. In known-failure mode require terminal failed and no successful response; in absent mode permit/require succeeded-without-response only if the existing public invocation protocol supports that distinct outcome (verify before freeze). Never treat default-bound fields as a response. An invocation denial produces an admission/refusal outcome and no candidate result obligation. The nontrivial guarantee is this result relation plus honest response presence, and contexts can forward/branch on it. A schema-valid `y=2` on `x=0` is an executable semantic negative control.

Candidate shape: one-member template, one request/one terminal outcome, zero nested invocations, zero effects, no lifecycle commands. Successful admission costs `(I,R,E)=(1,1,0)` at depth `d+1`; denied admission costs zero. These restrictions apply to candidates only; peer/wrapper contexts still compete legitimately. Independent A/B can implement different permitted value choices using distinct branch/arithmetic logic and different acyclic pure-step counts. This deliberately establishes contract refinement, not pairwise equivalence. Optional helper appears in the weak-contract and equal-charge scheduling probes as separately labeled profiles, without secretly changing Kp.

Bare/direct, sequential-followup, parallel-peer (both orientations), hidden internal caller communication, and at most one invocation-wrapper are **named finite templates**, unless an actual finite grammar enumerator is built. Preserve the distinction in census wording. Wrapper retains/forwards the child's status/presence/value according to an explicit table, then obtains its own succeeded/failed/cancelled outcome; it never impersonates the child outcome. Define each peer as a one-shot singleton invocation with no external effects; sequential S consumes the actual candidate response under its own explicit contract.

### Component relation

Check each candidate in isolation against K's finite open transition system, with an environment alphabet containing request, admission decision, delivery/consumption, permitted closure, and (effect profile only) authorization/receipt events. For every reachable candidate transition, an abstraction-preserving contract transition/stutter must exist. Required successful response has a well-founded progress obligation conditional on admission, open scope, available required inputs and fair local/protocol service; mere trace inclusion is insufficient because it allows perpetual silence. Validate every finite accepted payload and relevant residual environment state. Do not define conformance through passing every context.

To connect local conformance to contexts, explicitly include shared ledger/closure state in the relation and require stability under each allowed peer environment debit/closure transition. For this small bounded result the oracle can check the component relation first and then enumerate each declared context product. The latter yields bounded product evidence even if a general substitution proof remains open. A bad implementation must execute and reach a violated output/charge before the independent checker rejects it; static invalidity is not this control.

### Admissibility and resource rule

Define compatibility before selecting candidates: correct ports/provenance/correlation, disjoint private subjects, one root/one generation, finite context templates, permitted shared scope actions. Compatibility permits insufficient capacity and closure schedules; they remain in the safety/refusal census.

Define a separate success entitlement: for every reachable prefix, residual `(I,R,E)` must cover the sum of each participant's remaining declared demand including unadmitted wrapper/followup/helper demand. Already committed charges are subtracted exactly once; pending requests do not reserve capacity unless the actual protocol has reserved it. Prior legal spending is included in the initial residual ledger, or realized through a real provisioning prefix for runtime witnesses. No database edits. Include maximum depth of the whole path, and distinguish fixed static root/peer runs from dynamically charged member creation. Resource closure cannot be promised away for safety; eventual success additionally assumes no interfering closure and eventual delivery of all necessary declared input/receipt events.

Residual allowances `{0,1,2,3}` suffice for direct, sequential and peer boundary probes; wrapper-plus-followup/peer may need exactly3 dynamic invocations with singleton candidates. Depth `{0,1,2,3}` and effects `{0,1}` suffice for selected shapes. Freeze any excluded combination explicitly, and compute whole-context demand before asserting success entitlement. Insufficient-capacity cases must be included as admissible refusal cases, not eliminated to manufacture progress. Equal final totals and pointwise lower costs are not substitutes for this prefix reasoning.
