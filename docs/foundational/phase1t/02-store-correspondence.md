# Open Store correspondence for owning trees

Can the original open e/h kernel used in S be recovered at a leaf when other siblings spend the same physical ledger? Use the actual invocation-profile Store below, called **K_store_tree**. It has more cut points than S for source permission and fewer than a queue model for publication and inbox delivery. Its private steps are reductions of the bound retained programs, including reductions that can fault. This is a source argument for the pure, single-host, generation-one placement in the [contract](01-contract.md).

## States, attempts and transactions

A state contains each original run with PC, data (including undefined destinations), cursor, sequence and current authority, each original operation with source revision, first permission if decided, admission, binding, debit, captured intents, dispositions, outcome and delivery if decided, and per-observation recipient and consumption. It also contains actual resource-root membership, spend and the separate immediate caller at each invocation. Static occurrence paths are proof names. The runtime distinguishes commitments by (source subject, generation, committed sequence, ordinal). An invocation ID derives from namespace and original operation. Member identity derives from invocation and member role. Legal placement requires fresh noncolliding identities. Equal literal inputs, outputs or template IDs do not equate two operations.

| Owner and action | Precondition, effect and unsuccessful attempts |
|---|---|
| Run instruction | Commit checks current authority, same subject generation, unretired open run, sequence headroom and a validated bound program. Each successful instruction commits one successor projection and history row. An emit writes one immutable intent at the same time as its destination/updates. It incurs no admission charge. A receive commits bindings and marks its selected observation consumed at that same sequence. An End retains its PC and, for these singletons, closes the run and freezes precisely the already committed prefix in the same transaction. A failed reduction commits none of those changes. Stale/wrong generation, closed, overflow/size, or missing operands are distinct outcomes of attempts. [Commit](../../../internal/executor/store.go) · [Reduce](../../../internal/executor/program.go) · [execution/freeze](../../../internal/executor/composition_facts.go) |
| First source decision | On an original committed intent, AuthorizeIntent looks up its immutable descriptor and issuing revision. A matching saved row returns that historical result, with no second permission. A mismatched descriptor conflicts. A first decision tests revision, current subject generation, then retired and closed status except for a recognized bound reply. It records the source authority (run ID, epoch, sequence and revision), closure operation if any, allowed flag and raw reason. The source projection status at that decision is reconstructed from the corresponding history. Authorization is its own committed transaction, before actual admission. Reading a prior authorization cannot spend, deliver or select. [AuthorizeIntent](../../../internal/executor/messages.go) |
| Invocation service | AdmitInvocation obtains that permission and then, in a separate owner transaction, returns a saved admission if present. For a new original admission, in order it checks saved denial, current open source/revision, enclosing scope, declaration/target/generation, template existence, root catalogue, depth, input schema, immediate-parent template catalogue if any, capability grants, physical I then R. Scope includes the resource root's current open run and closures/results/non-success freezes up the actual invocation chain. An unrelated sibling's failure closes none of these scopes. A refusal retains its precise reason and has zero debit or creation. Acceptance retains the decision, fresh binding, original member(s) with declared initial state, invocation request observation for the entry member and the one original charge atomically. No state exists with an accepted but uncharged child. [AdmitInvocation and compositionScopeClosed](../../../internal/executor/invocation.go) · [deployment checks](../../../internal/executor/invocation_catalogue.go) |
| Bound reply service | DeliverMessage obtains the first or saved permission. compositionReplyBinding recognizes an entry member in the invocation protocol sending to its actual caller's subject, generation and entry-port obligation. Binding resolution checks descriptor and program identity. recordCompositionReply checks retained intent, nonempty transport, sizes, prior matching transport/admission and per-intent reply disposition. A new decision requires an allowed permission and entry-port send schema. Its accepted reason is recorded_reply. An additional transport identity may record the same underlying disposition once for that transport. No ordinary inbox observation results. Acknowledgment is a separate transport step. There is no current caller-open or ancestor-scope gate on this path. [Binding and recognition](../../../internal/executor/invocation.go) · [resolveCompositionProgram](../../../internal/executor/composition_binding.go) · [recordCompositionReply](../../../internal/executor/invocation_outcome.go) |
| Invocation settlement and delivery | PrepareInvocation reads readiness. No freeze gives members pending. Every captured bound reply, successful or failed member, must have an original disposition, else reply_admission. A successful freeze also checks descendant admissions/publications and known external obligations. Failed freezes do not generally join descendants. For an accepted singleton with one accepted reply the envelope carries its payload and member outcome; failure without reply gives failed/member_failed, success without reply gives failed/missing_reply. Multiple captured sends can yield failed/conflicting_replies. Refused calls yield rejected with the admission reason. SettleInvocation on a nonready case returns the pending reason without publishing. On first settlement the Store writes the publication, appends its outcome fact, writes the result row for an accepted invocation, and inserts the authenticated observation and delivery row, all in one transaction, with no externally schedulable intermediate cut. Repeating the original settlement reuses its publication and observation. Delivery does not require an open caller and does not select. [prepareCompositionScope and SettleInvocation](../../../internal/executor/invocation_outcome.go) |
| Actual selection and faults | Commit requires an unconsumed observation for this complete recipient run. Reduce compares kind, provenance, source, source generation, obligation and original operation against the actual receive operands. A structural mismatch is ineligible. Matching envelope schema is checked before binding; absent invocation responses delete each response destination. A malformed matching payload or a missing operand is an error. A later unguarded read can fault. selectReady skips ineligible observations and propagates other reduction errors. A fault, limit, cancelled driver, or stopped prefix cannot stand for a serviced blocked receive. Root completion is a separate SettleRoot after the outer run Ends. The model groups the root publication and its outcome fact into one event and projects away the accepted invocation result row, which repeats the published outcome. For ordinary messages, the second transaction after first permission uses admit on a message descriptor and its transport identity. It checks target existence, generation, retirement, open target, route grant for the intent revision and applicable schema. It inserts an ordinary-message observation only on acceptance. This path has no special bound-reply exemption and does not recheck the source's enclosing scope. The positive constructors only send bound replies. ## Projection onto the original open account

Fix one J occurrence at its actual binding. Keep its real e and possible h run, including every private computation, original request and all selected evidence. Reconstruct S's scratch caller at its e commitment/selection and keep scope open. Its synthetic terminal after selection never closes the real root. Use the original nominal correspondence for causal keys and keep every application value literal. Only admission of **this** J's S spends its original local q. Other accepted slots are removed from the projected ledger but retained in the full rooted history. The multiple-slot inequality and lifetime argument in the [tree proof](03-tree-theorem.md) establish the current numerical and source guards without conditioning the theorem on a child's eventual success.

Induct on a real open prefix. Before admission, a child has no instruction or selectable input. Atomic acceptance realizes the local admission/debit/request group, initialized at PC 0. A private commit has precisely the corresponding original operands, successful observation or absent-register behavior; sibling activity cannot write those registers or select that recipient's observation. Every genuine branch and pending-entry instruction remains present. For a local e/h invocation, the invoker's code has no End path before its required select. Every enclosing parent is still before its own final selection/End. Headroom survives other legal admissions and the original catalogue, scope, depth and payload guards pass. Keep first permission in the full history and project it to stutter only in S's coarser history. The later current admission realizes the local group. Every open original bound reply has stable revision/generation and correct bound payload even on the far side of sender End. Its disposition thus realizes the local open reply action. Freezes capture those original commitments. Publication reads their disposition and any requisite descendants. Project the atomic publication/delivery to the original ordered facts (or the two adjacent local transitions if represented separately). An interleaving solely between those facts need not have a Store realization. Selection by J is gated by the original S select first. Selection by e is gated by its actual original h await. All other work preserves this local state except this J's original S admission. These cases exhaust the productive local/open clauses, including all private steps. The implication is from actual prefixes to local paths with a finite prerequisite chain for a continuously owed service. It is not surjectivity on independently split local histories. [S original machine](../phase1s/02-correspondence.md) · [P scratch caller and service argument](../phase1p/02-preservation.md) · [R relocation](../phase1r/02-transport.md)

Open environment means stable authorities, legal original bindings, sufficient physical sizes and budgets, no outside closure, extra inputs/debits or pending release. The tree code establishes parent lifetimes separately. Weak service applies to an eligible original instruction **including private computation**, first decision, subsequent current admission, bound reply disposition, ready settlement/delivery, selection and root settlement, whenever continuously owed. Repeated saved lookups cannot service a different obligation. For an automatic pure run, deliverOrdinary handles internal delivery synchronously, selectReady considers runnable members and skips unmatched receives. Only external/adapter dispatch occupies worker capacity and E=0 here. A waiting parent's receive occupies no worker. A finite watchdog/fault is outside the serviced maximality claim. ## Cancellation boundaries outside the positive theorem

Assume an original committed intent, stable revision/generation, any necessary route/schema and no previously saved admission unless indicated. CancelRun here means an accepted open-to-cancelled transition. It changes that run's status, not every descendant run's status. For an invocation “source” is the run that committed the child Invoke. For a message/reply it is the sender. Rows describe the **first still-undecided** operation after the named cut.

| Cut | Invocation | Ordinary message | Original bound reply |
|---|---|---|---|
| Only ancestor/root cancelled, source and immediate recipient still open | First permission authorized. Current admission scope_closed. | First permission authorized. An eligible route to the still-open target can be accepted. | First permission authorized. Correct bound send recorded_reply. |
| Actual source cancelled before first permission | source_closed on first permission, then source_denied:source_closed at admission. | Same first decision and source_denied:source_closed at delivery. | Despite closed source, first permission authorized and correct reply recorded_reply. Its intent must already exist. |
| Source cancelled after an allowed first decision but before initial admission | Current admission source_closed, before scope test. | Saved permission stands. Can still be accepted at an open permitted target. | Saved permission stands. Correct reply recorded_reply. |
| Immediate recipient/caller cancelled, source stays open | If that run is the invoking source, apply the source row. If it is the source's own parent, current ancestry gives scope_closed. | First permission authorized, target_closed on first fresh transport admission to that cancelled target. | Correct send can be recorded_reply bound to the closed caller. A later settlement can deliver an outcome to that caller, which cannot commit a selection after closure. |
| Sender Ends before first permission | source_closed, then source_denied:source_closed. | Same first denial. | authorized then recorded_reply, including after an enclosing closure. Captured disposition is independent of selection. |
| Historical rows exist | Same admission/charge reused. Saved permission alone never establishes admission. | Identical transport and descriptor return the saved admission. Different transport requires its own admission; descriptor conflict on reused transport is ErrConflict. | Matching original disposition reused. No second bound reply counting toward publication. |

If revision or generation has changed at *first* permission, source_revision_changed or source_generation_changed takes precedence even for a bound reply. A nonreply retired source can receive source_retired. Other target reasons on the ordinary path include target_missing, target_retired, target_generation_changed, route_denied and schema_invalid. A bound reply can be schema_invalid. The table describes isolated cases; exact priority is given by the source switches. A denied first decision is historical even after a later change. An accepted already_terminal cancellation by itself supplies no new freeze. The retained S execution commits h's original bound reply, accepts operator CancelRun on O, commits h's successful End, records first permission authorized, then records recorded_reply to B on that same intent. The closed coarse kernel instead gives scope_closed. Stable generation/revision and the bound-reply exception explain the difference. Preserve S's observed prefix with no inferred subsequent settlement. The branching control uses that same order in an actual fork placement, cancels O alone and stops at the original disposition. The open projection excludes these histories; it makes no cancellation liveness or arbitrary Store-schedule equivalence claim.
