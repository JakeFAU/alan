# C_reason construction expectations — recorded before execution

Specification source: Phase1M assignment sections2,4,6; Task4 brief. These are
predeclared construction checks, not an independent reference or full census.
C_se is qualified at base1f71b56; its artifact bytes must remain unchanged.

One fixed parent commits original candidate then original S, consumes S then
candidate, and only then sets classification and terminates. S receives the
original id/value. Both handles and exact child status/reason/presence persist.
Original S must be succeeded/member_succeeded/present/id(original)/value0.
With valid S, candidate succeeded/member_succeeded/present/correct id/complement
sets answer and Success; failed/member_failed/absent sets candidate_failed and
Failure; failed/missing_reply/absent sets candidate_missing_reply and Failure.
Every other completed candidate or invalid S sets invalid_outcome and Failure.
Payload reads require true presence; request mode is never a parent decision.
Root/aggregate failure is member_failed even for candidate missing_reply.
Every completed classification write and terminal instruction follow both
selected original consumption histories. No ordinary report Send is added.

Representative public samples use id1/value0, original A/B answer, fail, absent,
pending, plus wrong-id answer, weak-a answer (wrong complement), deliberate-failure
absent, and existing S fail/absent controls. Correct answer candidate is id1/value1;
S remains id1/value0. Wrong-id retains id2 and is invalid_outcome; weak-a retains
value0 and is invalid_outcome. Invalid S is invalid_outcome after both consumptions.
DeliberateFailure receives one original absent request then executes Failure,
so candidate_failed is correct for its authentic member_failed observation.
This executable component mutation must be rejected by K1 requested-absent
component/profile checks later; it is not evidence of a conforming K1 absent result.
A/B absent instead retains missing_reply and sets candidate_missing_reply.

Candidate pending permits successful original S consumption, then stays open at
the original candidate await; no candidate publication, tag, root outcome or
terminal instruction. S pending keeps the first await open even if e completes.
S failure paired with candidate pending cannot terminate early.
No pending-release request, retry, fallback, wrapper or external effects.
Common I=R3/depth2/E0/fixed1/capacity1. Expected answer spending A+S2,
B+helper+S3; fail/absent/pending A2/B3; named local probes2.
Operational 200-step/200-dispatch and 1MiB byte limits need compiled/path/actual
evidence; no counts or sizes are assumed. Full8 all-input answer audited runs,
independent model/reference, local all-mode refinement and manuscript reconciliation
are later tasks. Preflight outputs are withheld from m2_model before its freeze.
