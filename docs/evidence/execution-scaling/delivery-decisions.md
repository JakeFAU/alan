## Runtime contract and limits

The owner index initializes only after independent Create/Open validation and successful activation. It recognizes validated static composition with one generation-one root run per root, ordinary adapter operations and empty terminal destinations. Dynamic invocation/templates and bindings, handoff, request-authority/reconciliation profiles, retained conflicting receipts, triggers and unsupported lifecycle/state fall back. The index carries candidate identities and affected work within one Store. Selection reloads authority and the original transactions independently enforce commitment, admission, reservation, result, settlement and publication. The Run loop, report shape and transaction error precedence remain governed by the existing contract. [Structural contract](structural-contract.md) · [Independent source design](reviews/structural-design.md)

Before trusted transactions and reused reads the guard checks pinned Store/connection identity, total changes, schema cookies, main data version, private limits/profile/namespace and applicable dispatch context. Successful supported commits publish precise deltas. Unsupported successful writes, anomaly/read failures, and failed commits disable reuse. Rollback publishes no delta and can conservatively invalidate reuse. Post-commit bookkeeping errors preserve the committed operation result and disable reuse if necessary. Direct commit paths preserve lock order. Fresh Open independently validates and reconstructs state. This qualification assumes cooperative single-host ownership and covers the witnessed local failure cuts. Distributed fencing, hostile writers, arbitrary storage faults and remote finality remain outside it.

`Store.ContinuationBasis(ctx, target)` is the sole public addition. It reads a coherent owner cut, selects the allowed exact original for the predecessor and checks referenced keyed evidence. An existing approval yields its historical basis. An empty retained-result digest means no result at the represented cut. For an unapproved slot that is the current owner read. For an approved slot it is the original decision, which can precede later retained evidence. The read conveys no authorization or proof of remote nonapplication. A change between the read and `ApproveContinuation` can make the basis stale. The write transaction retains its authoritative recheck. Full Inspect/Replay/Open keep their independent contracts. No schema, dependency, public report/signature or authority change accompanies this addition.
