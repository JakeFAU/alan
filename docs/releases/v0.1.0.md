# ALAN v0.1.0 release notes

This first public runtime is for Go developers building bounded agents that need to wait for input or a tool, survive a process restart, and retain the evidence behind a decision. The ticket router defines its own schema, program and adapter. Four separate processes admit a ticket, resume it, inspect its queue and replay its history. [Build the ticket router](../../README.md#build-your-own-durable-agent)

## Deployment and recovery

The minimum Go version is 1.27.3. Go 1.27.4 is recommended. Enable CGO and use a C compiler. One executor owns a SQLite store on a single host. The local Unix filesystem must support file locking, SQLite WAL and durable synchronization. The runtime pins `github.com/mattn/go-sqlite3` v1.14.53, which bundles SQLite 3.54.1. The cross-binding crash and reader comparison ran on Darwin/arm64. The research repository and historical experiments retain their own pins. [SQLite binding comparison](https://github.com/JakeFAU/alan/blob/6e7b765b92070ddc48462dbae003a7ff7caceac3/docs/qualification/sqlite-1.14.53/README.md)

A replacement owner can resume from committed state after process termination. Inspection and replay read retained decisions offline. The fault tests kill processes at specific persistence boundaries on a local filesystem. Physical power loss, device failure, network filesystems and multi-host execution are outside the qualified deployment model. The runtime also places explicit budgets on steps, dispatches and finite composition.

## Building and operating an agent

- Define the program in `author`, its data contracts in `schema` and application capabilities in `effects`. Use `runtime.Create`, `runtime.Open` and the documented methods on `runtime.Store` to operate the agent. Provide positive step and dispatch budgets for each run.
- Creation validates the initial computation before reserving a destination. Correct a definite provisioning error and retry at the same path. Preserve an interrupted or ambiguously committed destination for recovery.
- Bind retained asset IDs to each capability when provisioning a new corpus. The store records their versions and the prepared request. Older stores retain their original asset interpretation.
- Register trusted adapters in the host. Keep `Prepare` pure and bounded. In `Execute`, honor the context, perform one authorized operation and return the supplied request ID and key. A missing capability leaves the request available with no attempt spent.
- Once the runtime reserves a dispatch, the endpoint may have acted. A lost or malformed result can leave an ordinary paid request unknown across restart. It is never automatically sent a second time. Retrying an idempotent external operation requires the corresponding protocol and an endpoint that honors its key. ALAN gives no universal exactly-once guarantee for external effects. [Dispatch and uncertainty](../dispatch-admissions.md)
- Use Go error identities to distinguish invalid adapter output, unavailable capability and ineligible continuation. A recorded provider response can carry valid optional usage and an HTTP status of 100–599 when supplied. Readers distinguish an insufficient byte budget from corrupt retained evidence.

## Compatibility and distribution

The v0.1.x compatibility contract covers documented public calls, error identities and configuration meanings. Later v0 minor versions may require source changes. The store format has its own contract. The runtime reads original formats 3–16 and their corresponding asset-scoped formats 17–30. Older pre-scope readers reject the new formats. Before upgrading, stop the owner, back up the database and its committed WAL together, and verify a disposable copy. There is no general migration or downgrade operation. [Compatibility policy and format matrix](compatibility.md)

The Go module ships the application code, examples and runtime regression fixtures. Campaign archives and their source-specific evidence remain available in Git. Maintainers can exercise the packaged README application from a new module with empty caches and verify the candidate or published version against its checksums. [Consumer qualification](consumer.md)

## Deferred performance work

Measuring elapsed time for fallback observation scans and guarded candidate-list copies remains open. Earlier measurements count observation IDs checked and candidate-list entries copied on fixed workloads. Store creation validates and holds the initial database image in memory before publishing it. Larger provisions still need creation-latency and peak-memory measurements. [Performance evidence](../performance.md)
